# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Emberdeep**: an original 2D action metroidvania built with **Godot 4.7.2 stable**, using GDScript and the GL Compatibility renderer. All characters, enemies, places and art are original. Do not reuse names, designs or assets from existing games. Development happens in phases; `PROJECT_STATE.md` records what is done and what comes next. Update it, together with README.md and this file, at the end of every phase.

## Commands

Godot is **not on PATH**. The executable lives at:

```
G="/c/Users/user/Downloads/Godot_v4.7.2-stable_win64/Godot_v4.7.2-stable_win64_console.exe"
```

Use the `_console.exe` build so output reaches the terminal. Run everything from the project root.

| Task | Command |
|---|---|
| Import / reparse everything (run after adding or renaming files or `class_name`s) | `"$G" --headless --path . --import` |
| Run the test suite (exit 0 = pass) | `"$G" --headless --path . --fixed-fps 60 res://tests/test_runner.tscn` |
| Headless smoke run of the game | `"$G" --headless --path . --quit-after 300` |
| Play the game | `"$G" --path .` |
| Open the editor | `"$G" --path . -e` |
| Screenshot capture (needs a real window, not headless) | `"$G" --path . --fixed-fps 60 res://tools/capture.tscn -- <out_dir>` |

- **Running a single test:** comment out the other `await _run(...)` lines in `tests/test_runner.gd` `_ready()`. There is no filter flag.
- `--fixed-fps 60` makes each frame exactly one physics step and removes the real-time cap, so tests are deterministic and fast.
- To check output for problems, grep it for `ERROR|WARNING|SCRIPT ERROR`. A clean run prints none.

## Architecture

**Levels are data.** A level is a `LevelLayout` resource (`levels/*.tres`) whose `map` property is an ASCII grid of 16 px tiles. The legend is documented in `scripts/level/level_layout.gd`. `Level` (`scripts/level/level.gd`, the root of `scenes/levels/*.tscn`) builds the level at runtime:
- `TerrainBuilder` builds the physics. Solid cells are greedily merged into rectangles (`LevelLayout.merge_rects`) on one `StaticBody2D`. `=` cells become one-way slabs. `^` cells become spike `Hitbox`es with `is_hazard`. A closed boundary wall is added around the map.
- `TerrainRenderer` draws all terrain art in `_draw()`. Decoration is seeded by tile coordinates.
- Entities (`P`, `C`, `E`, `*`) are instanced from PackedScenes into the `Actors` node. Object ids are `"<level_id>/<kind>_<x>_<y>"`.

To change level geometry, edit the `.tres` map text. The cavern map was first generated by a Python script, which is not in the repo; edit the map directly. `test_layout_is_valid` checks the entity counts and that every entity has footing.

**Combat is component-based** (`scripts/components/`):
- A `Hitbox` (Area2D) **polls** `get_overlapping_areas()` every physics frame instead of using `area_entered`. This lets a hitbox that turns on while already overlapping a target still connect. One-shot hitboxes (attacks) hit each target once per activation. `continuous` hitboxes (contact damage, spikes) keep trying, and the target's invulnerability throttles them.
- A `Hurtbox` only accepts or rejects a hit (`invulnerable`) and emits `hit_received(hitbox)`. The owner applies damage, knockback and state changes.
- `Health` emits `changed`, `damaged` and `died`. The HUD listens to `changed`.

**Collision layers.** Names are set in `project.godot`; bits are written as literals in scenes and code.

| Layer | Bit | Used by |
|---|---|---|
| 1 world | 1 | rock (`Solids`) |
| 2 player | 2 | player body; checkpoints and pickups mask this |
| 3 enemy | 4 | enemy bodies |
| 4 player_hurtbox | 8 | player Hurtbox; enemy contact and spike Hitboxes mask this |
| 5 enemy_hurtbox | 16 | enemy Hurtboxes; the player's attack Hitbox masks this |
| 7 one_way_platforms | 64 | slabs. The player drops through by clearing this bit from its mask for a moment |

Bodies use mask `65` (world plus platforms). Player and enemy bodies don't collide with each other; contact damage goes through hit/hurtboxes instead.

**Actors** are `CharacterBody2D`s with an `enum State` and a `match` in `_physics_process`. Each has a separate `*_visual.gd` child that draws placeholder art procedurally and reads the actor's public state (`state`, `facing`, `flash_time`, and so on). Gameplay scripts never draw.
- `Player` (`scripts/player/player.gd`) has the states NORMAL, DASH, HURT and DEAD. One `AttackHitbox` serves every attack direction: `_start_attack` rotates `AttackPivot`, and for the down strike also moves it `down_strike_offset` lower. The down strike only happens in the air; on the ground Down + Attack swings forward. A down-strike hit bounces the player once per activation (`_can_pogo`) and does not refund the air dash. `_end_attack()` is the single place that ends an attack. Its timers handle coyote time, jump buffering, the dash cooldown, attack activity and invulnerability. Hazard hits freeze the player, then teleport them to `_safe_position`, the last spot where both feet were on solid ground.
- `Gloomshell` (`scripts/enemies/gloomshell.gd`) cycles PATROL → TELEGRAPH → CHARGE → RECOVER and also has HURT and DEAD states. It is stagger-immune while charging. A `LedgeCheck` raycast stops it walking off ledges.

**Hit-stop** lives in the `GameState` autoload because `Engine.time_scale` outlives scenes. `GameState.hit_stop(duration, time_scale)` slows the game; overlapping calls take the longest remaining duration and never add up. The timer counts real time as physics ticks (`1 / physics_ticks_per_second`) in `_physics_process` with `PROCESS_MODE_ALWAYS`. Do not use the frame delta for it: that delta is already scaled, and a delta computed before the hit would end the stop at once. `cancel_hit_stop()` runs on pause, on `respawn()`, on `reset()` and in `Level._ready()`, so a reload always starts at normal speed. The player calls `hit_stop` only from `hit_landed`, so misses never freeze.

**Effects** (`scripts/effects/`, `scenes/effects/`) are one-shot procedural `Node2D`s that free themselves. `ImpactBurst` is spawned by the player on each landed hit, into the player's parent, and reuses `PlayerVisual`'s flame colors.

**Persistence.** The `GameState` autoload holds the active checkpoint and the collected pickup ids. On death, `Level` waits `GameState.RESPAWN_DELAY` and then calls `GameState.respawn()`, which reloads the current scene. The new `Level` spawns the player at the checkpoint and skips pickups already collected. Enemies reset on reload by design.

## Conventions

- Tunables are `@export` variables on the actor script, grouped with `@export_group`. Don't hard-code gameplay numbers in other places.
- Use `class_name` for anything that is referenced across files. Use static typing throughout. Tabs indent `.gd` files.
- Scenes are written by hand in text format (`[gd_scene format=3]`, no uids). Godot generates `*.gd.uid` files on import; keep them.
- Input actions are defined in `project.godot`: `move_left/right/up/down`, `jump`, `attack`, `dash`, `pause`. Read input only in `_physics_process`.
- **Test timing:** tests resume on the `physics_frame` signal, before nodes process. An `Input.action_press()` made there is first seen one physics step later, so use `press(...)` then `await frames(2)` before asserting on the reaction. Build small arenas in code (`add_floor`, `make_layout` with `TerrainBuilder`) rather than loading the full level, unless the test is about the level.
- Hit-stop eats game time: for a few frames after a landed hit, timers such as the attack cooldown advance slower. Allow for it in frame counts, or set `hit_stop_duration = 0` when a test is about something else. `_run` cancels hit-stop between tests.
- Never call `GameState.respawn()` in tests. It reloads the *current* scene, which in tests is the runner itself.
